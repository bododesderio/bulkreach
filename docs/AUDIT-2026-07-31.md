# BulkReach — Full Audit & Master Plan
**Date:** 2026-07-31 · **Author:** Bodo Desderio, Rooibok Technologies

A ten-lens senior-engineer audit (architecture, code quality, debugging, performance,
clean-architecture, backend systems, frontend, tech-lead, security, DevOps) plus a live
end-to-end Playwright walk of every client and superadmin flow against a freshly-seeded
running stack. Seven specialist passes were run in parallel and cross-corroborated.

**Overall verdict:** BulkReach is a genuinely strong, feature-complete build — the payments
state machine and the auth/session subsystem are production-grade. The risks are concentrated
in a handful of **scale, quota-integrity, and operational** decisions, not in correctness of the
hard parts. **No rewrite is warranted.** A focused scale-hardening sprint plus the operational
layer (CI/backups/monitoring) converts this into a launch-ready platform.

## 2. Unified findings register (deduplicated, ranked)

Corroboration in brackets — findings independently raised by more than one lens are the highest-confidence.

### 🔴 Critical / High — correctness, money, availability
- **[FIXED] SSE connection leak** *(perf H1 + arch C1)*.
- **[FIXED] Daily quota unenforceable** *(bug HIGH-1)*.
- **[FIXED] `manually_assigned` survives settlement** *(bug HIGH-3)*.
- **[PLANNED] Monthly quota is a non-atomic TOCTOU** *(arch C6 + bug HIGH-2)* — `enforce_send` reads used but never *reserves*; N concurrent `/send` all see used=0 and overspend (e.g. 5×5000 on a 5000 plan → 25 000 sent). Metering is post-hoc in the engine. **Fix:** atomic `INCRBY` reserve-and-refund on the Redis monthly counter at queue time; drop/reconcile the post-hoc `consume`. *(Phase 1)*
- **[PLANNED] Recipient materialization is O(n) flushes** *(perf H2 + arch C3)* — one `flush()` per recipient (up to 20k) at send time. **Fix:** client-generate `CampaignContact.id`, `add_all`/Core bulk insert. Turns a multi-second send into sub-second. *(Phase 1)*
- **[FIXED via indexes] Missing `created_at`/status indexes** *(perf H3/M5 + arch C12)*.
- **[PLANNED] Admin surface recomputes platform-wide aggregate maps per click** *(perf H4/M1)* — `_mrr_map`/`_messages_map` scan whole tables to read one account's number. **Fix:** account-scoped scalar queries + restrict list maps to shown IDs. *(Phase 1)*
- **[PLANNED] API-key auth is an O(n) bcrypt scan + timing oracle** *(arch C4)* — verifies every active key per request. **Fix:** indexed sha256/prefix lookup, then verify one row. *(Phase 1)*

### 🟡 Medium
- **[FIXED] SSRF via logo_url** *(sec H1)*; **[FIXED] reset revocation** *(sec H2)*; **[FIXED] auth rate limits** *(sec M2)*; **[FIXED] role guards** *(sec L2)*.
- **[PLANNED] Stored XSS on the public managed-approve page** *(sec M1)* — `dangerouslySetInnerHTML` of `copy_email_body`. **Fix:** DOMPurify on render + sanitize on write. *(Phase 3)*
- **[PLANNED] Impersonation is always full-access; only start/stop audited** *(sec M3 + live #14)* — stamp `imp_email` on every write under an impersonation token; real server-side read-only mode; revocable impersonation session. *(Phase 3)*
- **[PLANNED] `python-jose==3.3.0` — CVE-2024-33663/33664, unmaintained** *(sec M4)* — migrate to PyJWT. *(Phase 3)*
- **[PLANNED] `account_summary` loads all campaigns into Python** *(perf M2 + arch C7)* — push to SQL `SUM`/`date_trunc`. *(Phase 1)*
- **[PLANNED] Domain layer raises `HTTPException`; the worker swallows it** *(arch C2)* — a scheduled campaign hitting a quota gate silently fails. **Fix:** domain exceptions + API translation + worker reacts with a notification. *(Phase 6)*
- **[PLANNED] Blank status badges across tables** *(live #5 + FE M4)* — inconsistent badge component. *(Phase 4)*
- **[PLANNED] Mock data mixed into admin** *(live #6 + FE H6/M5/M10)* — overview managed-queue/provider-health, `/admin/campaigns` "Live activity", ClientsTable seed. *(Phase 4)*
- **[PLANNED] Mid-flight cancel only honored between retry rounds** *(bug MEDIUM-2)* — large single-round campaigns can't be cancelled. **Fix:** status check inside the batch loop. *(Phase 1)*
- **[PLANNED] Trial decrement is non-atomic RMW** *(bug MEDIUM-1)* — conditional atomic UPDATE. *(Phase 1)*

### 🟢 Low / polish
Access token in `localStorage` (arch C8), dead CORS config (C9), two "trial" notions (C10),
token `aud`/`iss` unpinned (C11), path-traversal on local upload filename (sec L1), archive log
uses proxy IP (sec L3), opt-in MoMo/Airtel webhook secret (sec L4), footer dead links, plan
`display_order` all 100, retention copy 24 vs 6 months, no dark-mode toggle (FE H2 — CONTEXT's
"dark-mode verified" is **stale**), reconcile_stale session reuse, 0-UGX proration charge.

### ✅ Verified secure / solid (no action)
SQL injection (bound params throughout), SSTI/email XSS (Jinja2 sandbox + autoescape + merge-tag
allowlist), **payment integrity** (server-authoritative amount, write-before-call, `FOR UPDATE`,
verify amount+currency fail-closed, idempotent refunds, webhook re-verify), **admin gating** (66
routes double-guarded), **multi-tenant IDOR** (account_id scoping into the service layer), Fernet
fail-closed secrets, rotating refresh-token theft detection, dual login limiter + trusted-proxy XFF.

## 3. Master plan (phased, no rewrite)

**Phase 0 — Emergency hardening.** ✅ *Done this session* (Section 1).

**Phase 1 — Scale-hardening sprint** *(the highest-value work)* — ✅ **mostly DONE** (commit `aa4510a`)
Removes every mechanism by which one tenant degrades the platform or over-sends.
1. ✅ Quota **reserve-and-refund** — atomic INCRBY reserve at `enforce_send`, unsent remainder refunded by the engine; obsolete Layer-3 `monthly_exhausted` pause removed. Closes the monthly TOCTOU. *(bug HIGH-2, arch C6)*
2. ✅ **Bulk-insert** recipients/messages (app-generated IDs, single flush). *(perf H2, arch C3)*
3. ✅ **Account-scope** the admin detail/suspend aggregate queries. *(perf H4)*
4. ✅ **SQL-aggregate** `account_summary` (count/sum + grouped daily + LIMIT 10). *(perf M2, arch C7)*
5. ⏸️ **Fast API-key lookup** — *deferred by design*: no key-issuance endpoint exists yet (scan is over 0 rows). A forward note in `dependencies.py` mandates an indexed sha256 lookup before the create-key endpoint ships. *(arch C4)*
6. ⏸️ **Cache the auth principal** — *deferred by design*: conflicts with the "suspend blocks immediately" invariant (`get_current_user` re-checks status every request). Needs synchronous cache-invalidation at every suspend/close/role-change site first. *(arch caching)*
7. ✅ Cancel-inside-the-batch-loop. *(bug M-2)*
Still open in Phase 1 scope: trial-decrement atomicity *(bug M-1)*, restrict list-view maps to shown IDs *(perf M1)*.

**Phase 2 — Delivery-Report (DLR) + suppression** — ✅ **DONE** (commit `9765645`)
Per-provider inbound delivery/bounce/complaint webhooks (`POST /webhooks/dlr/{provider}` — Africa's
Talking, Mailgun w/ HMAC verify, SendGrid, simulator) → real `delivered`/`bounced`/`undelivered`/
`complained` message states + campaign `delivered`/`bounced` counters (migration `f1a4c6e8b2d3`) →
auto-suppression on hard bounce/complaint. Per-account **suppression list** (enforced at
materialisation, plus a list/add/remove router). `compute_stats` is DLR-aware. 108 tests.
*Remaining polish:* inbound-SMS STOP handling, delivery numbers in the frontend campaign UI + PDF.

**Phase 3 — Security hardening**
Migrate `python-jose`→PyJWT; DOMPurify the managed-approve body; impersonation audit-stamping +
real read-only mode + revocable session; single-use reset token; mandatory MoMo/Airtel webhook
secret in prod; move access token out of `localStorage`; sanitize upload filenames; archive log
via `client_ip()`.

**Phase 4 — Frontend production polish**
Adopt React Query behind hooks (it's installed but unused); decide dark-mode (implement or remove
`next-themes`); extract a shared `components/ui` layer (`Card`, `StatusBadge` — fixes the blank
badges, `Field` with built-in autocomplete/labels, `Modal` with focus-trap, `DataState`); unified
`AppShell` with the mobile drawer for admin; replace remaining mock admin data with live; a11y
sweep (labels, contrast, reduced-motion).

**Phase 5 — Operational readiness (pre-launch, DevOps)** *(drafts ready in `infra/deploy-drafts/`)*
Adopt the CI pipeline (lint/typecheck/test → build → one-service-at-a-time deploy); Postgres +
ClickHouse + MinIO **backups with a rehearsed restore** + off-site copy; Sentry (api + web) +
Uptime-Kuma status page + ARQ worker heartbeat; `/health/ready` that pings dependencies; harden
weak compose defaults (`pw`/`minio123`), set `ANON_PEPPER` explicitly; add swap; tune resource limits.

**Phase 6 — Targeted architecture cleanup (optional)**
`app/domain/exceptions.py` + one FastAPI handler + worker reacts (stops HTTP leaking into the
domain and the silent scheduled-campaign failure); break the ~24 function-local import cycles by
moving `notifications`/`quota` to a lower layer. Minimal, not a rewrite.

**Infrastructure decision (tech-lead):** launch with **live Postgres + Redis + S3/MinIO only**;
run the archive as a *schema* in the live cluster (already a URL switch) and keep ClickHouse behind
its existing feature flag until analytics volume justifies it. Simplicity now, the abstraction is
already in place. **Do not** reach for Kubernetes.
